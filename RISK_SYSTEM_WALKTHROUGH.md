# Building a Risk System with OpenACR

A hands-on walkthrough of building a multi-counterparty risk management engine
using OpenACR's relational data model and code generation. Each section
documents the commands run, the expected output, and the key concepts at play.

By the end you will have a working C++ program that loads positions and
market data from ssimfiles, calculates exposure and P&L per counterparty,
checks risk limits, and prints a full risk report -- with zero hand-written
serialization or data-loading code.

## Introduction and Architecture

### What We Are Building

A risk engine that:

1. Loads reference data (instruments, counterparties), positions, and risk
   limits from ssimfiles on startup -- automatically, via amc-generated code.
2. Calculates per-position mark-to-market value and daily P&L.
3. Aggregates exposure by counterparty and by instrument type.
4. Checks each counterparty's risk limits and flags breaches or warnings.
5. Prints a formatted risk report to stdout.

### The Data Model

Six ssimfiles form a relational schema:

```
 dev.instrtype                  dev.limittype
 ┌──────────────┐               ┌───────────────┐
 │ instrtype PK │               │ limittype  PK  │
 │ comment      │               │ comment        │
 └──────┬───────┘               └───────┬────────┘
        │ 1:N                           │ 1:N
        ▼                               ▼
 dev.instrument                 dev.risklimit
 ┌──────────────────┐           ┌────────────────────────┐
 │ instrument PK    │           │ risklimit PK           │
 │ instrtype   FK───┤           │   = cpty.limittype     │
 │ name             │           │ cpty        FK─────────┤──► dev.cpty
 │ price            │           │ limittype   FK─────────┤──► dev.limittype
 │ prev_close       │           │ limit_value            │
 └──────────────────┘           │ warn_pct               │
        ▲                       └────────────────────────┘
        │ FK
 dev.position                   dev.cpty
 ┌──────────────────┐           ┌──────────────┐
 │ position PK      │           │ cpty     PK  │
 │   = cpty.instr   │           │ comment      │
 │ cpty       FK────┤──────────►└──────────────┘
 │ instrument FK────┤
 │ qty              │
 │ avg_cost         │
 └──────────────────┘
```

Composite keys (`position` = `cpty.instrument`, `risklimit` = `cpty.limittype`)
are decomposed automatically by fldfunc expressions (`.RL` and `.RR`), giving
you the foreign key fields for free.

### The In-Memory Database

After `amc` generates code, the in-memory layout looks like this (output of
`amc_vis risk_engine.%`):

```
/ risk_engine.FDb
|Tpool cpty------------------->/ risk_engine.FCpty
|Thash ind_cpty--------------->|
|Llist zd_cpty---------------->|
|Tpool position----------------|---->/ risk_engine.FPosition
|                              |<----|Upptr p_cpty
|Thash ind_position------------|---->|
|                              |Llist zd_position--->|
|Llist zd_position-------------|---->|
|Tpool instrument-->/ risk_engine.FInstrument  |     |
|Thash ind_instrument-->|      |     |               |
|                       |<-----|-----|Upptr p_instrument
|Llist zd_instrument--->|      |     -
|Tpool instrtype-->/ risk_engine.FInstrtype
|                  |Llist zd_instrument--->|
|Llist zd_instrtype-->|                   |
|Thash ind_instrtype-->|                  |
|                  |<-----|Upptr p_instrtype
|                  -      -
|Tpool risklimit---|---->/ risk_engine.FRisklimit
|                  |<----|Upptr p_cpty
|                  |Llist zd_risklimit-->|
|Thash ind_risklimit--->|
|Llist zd_risklimit---->|
|Tpool limittype-->/ risk_engine.FLimittype
|Thash ind_limittype-->|
-                      -
```

Every pool (`Tpool`), hash table (`Thash`), linked list (`Llist`), and
pointer (`Upptr`) is generated by `amc`. You define the schema; `amc`
writes the C++.

## Step 1: Design the Data Model

We create six ssimfiles. The first three are simple lookup tables; the
remaining three have foreign keys, custom fields, and composite keys.

### 1a. Lookup Tables

```bash
# Instrument types
acr_ed -create -ssimfile dev.instrtype -write -amc:N

# Counterparties
acr_ed -create -ssimfile dev.cpty -write -amc:N

# Limit types
acr_ed -create -ssimfile dev.limittype -write -amc:N
```

Each `acr_ed -create -ssimfile` command creates:

- An empty data file at `data/dev/<table>.ssim`
- Schema entries in `dmmeta.ctype`, `dmmeta.field`, `dmmeta.ssimfile`

### 1b. Instruments (with foreign key and extra fields)

```bash
# Create the table
acr_ed -create -ssimfile dev.instrument -write -amc:N

# Foreign key to instrtype
acr_ed -create -field dev.Instrument.instrtype -arg dev.Instrtype -reftype Pkey -write -amc:N

# Display name
acr_ed -create -field dev.Instrument.name -arg algo.Smallstr50 -write \
  -comment "Display name" -amc:N

# Current market price
acr_ed -create -field dev.Instrument.price -arg double -dflt 0.0 -write \
  -comment "Current market price" -amc:N

# Previous close (for daily P&L)
acr_ed -create -field dev.Instrument.prev_close -arg double -dflt 0.0 -write \
  -comment "Previous close price" -amc:N
```

The `instrtype` field with `reftype:Pkey` means "the value of this field must
exist as a primary key in `dev.instrtype`." `acr -check` enforces this.

### 1c. Positions (composite key: counterparty x instrument)

```bash
acr_ed -create -ssimfile dev.position \
  -subset dev.Cpty -subset2 dev.Instrument -separator . \
  -write -amc:N

acr_ed -create -field dev.Position.qty -arg double -dflt 0.0 -write \
  -comment "Number of units held" -amc:N

acr_ed -create -field dev.Position.avg_cost -arg double -dflt 0.0 -write \
  -comment "Average cost per unit" -amc:N
```

The `-subset dev.Cpty -subset2 dev.Instrument -separator .` flags tell
`acr_ed` to create a composite primary key of the form `cpty.instrument`
(e.g., `desk_a.AAPL`). Under the hood this creates two fldfunc fields:

| Field | Expression | Example |
|-------|-----------|---------|
| `dev.Position.cpty` | `.RL` (scan Right for `.`, take Left) | `desk_a` |
| `dev.Position.instrument` | `.RR` (scan Right for `.`, take Right) | `AAPL` |

Both are foreign keys (`reftype:Pkey`) pointing back to `dev.Cpty` and
`dev.Instrument`, enforced by `acr -check`.

### 1d. Risk Limits (composite key: counterparty x limit type)

```bash
acr_ed -create -ssimfile dev.risklimit \
  -subset dev.Cpty -subset2 dev.Limittype -separator . \
  -write -amc:N

acr_ed -create -field dev.Risklimit.limit_value -arg double -dflt 0.0 -write \
  -comment "Maximum allowed value" -amc:N

acr_ed -create -field dev.Risklimit.warn_pct -arg double -dflt 0.8 -write \
  -comment "Warning threshold as fraction of limit" -amc:N
```

Same composite-key pattern: `risklimit` = `cpty.limittype`, e.g.,
`desk_a.gross_exposure`.

### Verify the Schema

```bash
acr field:dev.Position.%
```

Expected output:

```

dmmeta.field  field:dev.Position.cpty        arg:dev.Cpty         reftype:Pkey  dflt:""   comment:""
dmmeta.field  field:dev.Position.instrument  arg:dev.Instrument   reftype:Pkey  dflt:""   comment:""
dmmeta.field  field:dev.Position.qty         arg:double           reftype:Val   dflt:0.0  comment:"Number of units held"
dmmeta.field  field:dev.Position.avg_cost    arg:double           reftype:Val   dflt:0.0  comment:"Average cost per unit"
dmmeta.field  field:dev.Position.comment     arg:algo.Comment     reftype:Val   dflt:""   comment:""
```

## Step 3: Create the Executable and In-Memory Schema

This is the most intricate step. We create a C++ target, then define its
in-memory data structures so that `amc` generates all the loading, indexing,
and cross-referencing code.

### 3a. Create the Target

```bash
acr_ed -create -target risk_engine -write -amc:N
```

This scaffolds:

- `cpp/risk_engine/risk_engine.cpp` (main source, with a Hello World stub)
- `include/risk_engine.h` (header)
- Generated files under `include/gen/` and `cpp/gen/`
- Build metadata in `dev.target`, `dev.targsrc`, `dev.targdep`
- A `command.risk_engine` ctype for command-line options

### 3b. Create In-Memory Pools with Hash Indexes

For each ssimfile type, we create an in-memory ctype with a Tpool (memory
pool) and a Thash (hash table for O(1) lookup by primary key):

```bash
acr_ed -create -ctype risk_engine.FInstrtype -pooltype Tpool -indexed -write -amc:N
acr_ed -create -ctype risk_engine.FCpty      -pooltype Tpool -indexed -write -amc:N
acr_ed -create -ctype risk_engine.FLimittype -pooltype Tpool -indexed -write -amc:N
acr_ed -create -ctype risk_engine.FInstrument -pooltype Tpool -indexed -write -amc:N
acr_ed -create -ctype risk_engine.FPosition   -pooltype Tpool -indexed -write -amc:N
acr_ed -create -ctype risk_engine.FRisklimit  -pooltype Tpool -indexed -write -amc:N
```

At this point each in-memory type has only a primary key field (e.g.,
`risk_engine.FInstrument.instrument` typed as `algo.Smallstr50`). It knows
nothing about the ssimfile fields like `price` or `qty`.

### 3c. Add Base Fields (the crucial step)

The `Base` reftype tells `amc` to inherit all fields from a parent ctype.
This is how the in-memory types acquire the ssimfile fields (price, qty,
etc.) and how the tuple reader maps `dev.instrument` tuples to the
`risk_engine.FInstrument` pool.

**Important**: the Base field must be the first field in the ctype. Since
`acr_ed` already created a primary key field, we need to delete it first so
the Base-inherited primary key takes its place.

```bash
# For each type: delete the auto-created primary key, then add Base.
# The Base brings the primary key and all other fields from the ssimfile ctype.

# FInstrtype
acr field:risk_engine.FInstrtype.instrtype -del -write
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FInstrtype.base arg:dev.Instrtype reftype:Base dflt:"" comment:""
EOF

# FCpty
acr field:risk_engine.FCpty.cpty -del -write
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FCpty.base arg:dev.Cpty reftype:Base dflt:"" comment:""
EOF

# FLimittype
acr field:risk_engine.FLimittype.limittype -del -write
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FLimittype.base arg:dev.Limittype reftype:Base dflt:"" comment:""
EOF

# FInstrument
acr field:risk_engine.FInstrument.instrument -del -write
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FInstrument.base arg:dev.Instrument reftype:Base dflt:"" comment:""
EOF

# FPosition
acr field:risk_engine.FPosition.position -del -write
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FPosition.base arg:dev.Position reftype:Base dflt:"" comment:""
EOF

# FRisklimit
acr field:risk_engine.FRisklimit.risklimit -del -write
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FRisklimit.base arg:dev.Risklimit reftype:Base dflt:"" comment:""
EOF
```

After this, `risk_engine.FInstrument` inherits all of `dev.Instrument`'s
fields: `instrument`, `instrtype`, `name`, `price`, `prev_close`, `comment`.
The generated `TableId` enum will map `dev.instrument` tuples to
`risk_engine.FInstrument`, enabling automatic loading.

You also need to re-add the `thash` records since deleting the primary key
field cascade-deleted them:

```bash
cat <<EOF | acr -insert -write
dmmeta.thash field:risk_engine.FDb.ind_instrtype hashfld:dev.Instrtype.instrtype unique:Y comment:""
dmmeta.thash field:risk_engine.FDb.ind_cpty hashfld:dev.Cpty.cpty unique:Y comment:""
dmmeta.thash field:risk_engine.FDb.ind_limittype hashfld:dev.Limittype.limittype unique:Y comment:""
dmmeta.thash field:risk_engine.FDb.ind_instrument hashfld:dev.Instrument.instrument unique:Y comment:""
dmmeta.thash field:risk_engine.FDb.ind_position hashfld:dev.Position.position unique:Y comment:""
dmmeta.thash field:risk_engine.FDb.ind_risklimit hashfld:dev.Risklimit.risklimit unique:Y comment:""
EOF
```

### 3d. Add Upward Pointers (Upptr)

Upptr fields are resolved automatically during data loading via xref
via-paths. When a position is loaded, the system looks up its `cpty` value
in the `ind_cpty` hash table and stores a pointer.

```bash
# Instrument -> Instrtype
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FInstrument.p_instrtype arg:risk_engine.FInstrtype reftype:Upptr dflt:"" comment:""
dmmeta.xref field:risk_engine.FInstrument.p_instrtype inscond:true via:risk_engine.FDb.ind_instrtype/dev.Instrument.instrtype
EOF

# Position -> Cpty
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FPosition.p_cpty arg:risk_engine.FCpty reftype:Upptr dflt:"" comment:""
dmmeta.xref field:risk_engine.FPosition.p_cpty inscond:true via:risk_engine.FDb.ind_cpty/dev.Position.cpty
EOF

# Position -> Instrument
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FPosition.p_instrument arg:risk_engine.FInstrument reftype:Upptr dflt:"" comment:""
dmmeta.xref field:risk_engine.FPosition.p_instrument inscond:true via:risk_engine.FDb.ind_instrument/dev.Position.instrument
EOF

# Risklimit -> Cpty
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FRisklimit.p_cpty arg:risk_engine.FCpty reftype:Upptr dflt:"" comment:""
dmmeta.xref field:risk_engine.FRisklimit.p_cpty inscond:true via:risk_engine.FDb.ind_cpty/dev.Risklimit.cpty
EOF
```

The `via:` path reads as: "look up the value of `dev.Position.cpty` (a
fldfunc field extracted from the composite key) in the `ind_cpty` hash
table, and store the result in `p_cpty`."

### 3e. Add Group-By Linked Lists

These let us efficiently iterate "all positions for a given counterparty"
or "all instruments of a given type":

```bash
# Cpty -> its Positions (cascade delete)
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FCpty.zd_position arg:risk_engine.FPosition reftype:Llist dflt:"" comment:"Positions held by this counterparty"
dmmeta.llist field:risk_engine.FCpty.zd_position havetail:Y havecount:Y comment:""
dmmeta.xref field:risk_engine.FCpty.zd_position inscond:true via:risk_engine.FPosition.p_cpty
dmmeta.cascdel field:risk_engine.FCpty.zd_position comment:""
EOF

# Cpty -> its Risk Limits (cascade delete)
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FCpty.zd_risklimit arg:risk_engine.FRisklimit reftype:Llist dflt:"" comment:"Risk limits for this counterparty"
dmmeta.llist field:risk_engine.FCpty.zd_risklimit havetail:Y havecount:Y comment:""
dmmeta.xref field:risk_engine.FCpty.zd_risklimit inscond:true via:risk_engine.FRisklimit.p_cpty
dmmeta.cascdel field:risk_engine.FCpty.zd_risklimit comment:""
EOF

# Instrtype -> its Instruments (cascade delete)
cat <<EOF | acr -insert -write
dmmeta.field field:risk_engine.FInstrtype.zd_instrument arg:risk_engine.FInstrument reftype:Llist dflt:"" comment:"Instruments of this type"
dmmeta.llist field:risk_engine.FInstrtype.zd_instrument havetail:Y havecount:Y comment:""
dmmeta.xref field:risk_engine.FInstrtype.zd_instrument inscond:true via:risk_engine.FInstrument.p_instrtype
dmmeta.cascdel field:risk_engine.FInstrtype.zd_instrument comment:""
EOF
```

### 3f. Add Global Iteration Lists

These attach every loaded record to a global linked list on `FDb` so we can
iterate all counterparties, all positions, etc.:

```bash
acr_ed -create -field risk_engine.FDb.zd_cpty -write -comment "All counterparties" -amc:N
acr_ed -create -field risk_engine.FDb.zd_instrument -write -comment "All instruments" -amc:N
acr_ed -create -field risk_engine.FDb.zd_position -write -comment "All positions" -amc:N
acr_ed -create -field risk_engine.FDb.zd_risklimit -write -comment "All risk limits" -amc:N
acr_ed -create -field risk_engine.FDb.zd_instrtype -write -comment "All instrument types" -amc:N
```

### 3g. Configure Automatic Data Loading

The `finput` records tell the engine which pools should be populated from
ssimfiles on startup. The `floadtuples` mechanism (set up when we created
the target) reads the `data/` directory and dispatches tuples to the correct
pool based on the tuple header (e.g., `dev.instrument` maps to
`risk_engine.FInstrument` because of the Base relationship).

```bash
cat <<EOF | acr -insert -write
dmmeta.finput field:risk_engine.FDb.instrtype extrn:N update:N strict:Y comment:""
```

## Step 4: Write the C++ Source

Replace the generated stub in `cpp/risk_engine/risk_engine.cpp` with the
risk engine logic. The entire program is about 170 lines -- all data loading,
indexing, and cross-referencing is handled by amc-generated code.

```cpp
// Target: risk_engine (exe)
// Source: cpp/risk_engine/risk_engine.cpp

#include "include/algo.h"
#include "include/risk_engine.h"

static tempstr FmtDollar(double val) {
    tempstr out;
    if (val < 0) {
        out << "-$";
        algo::double_PrintWithCommas(-val, out, 2);
    } else {
        out << "$";
        algo::double_PrintWithCommas(val, out, 2);
    }
    return out;
}

static tempstr FmtPct(double val) {
    tempstr out;
    algo::double_PrintPrec(val * 100, out, 1, false, false);
    out << "%";
    return out;
}

static void PrintHeader(algo::strptr title) {
    prlog("");
    prlog("========================================================================");
    prlog("  " << title);
    prlog("========================================================================");
}

static void PrintSubheader(algo::strptr title) {
    prlog("");
    prlog("  --- " << title << " ---");
}

static void RunRiskReport() {
    PrintHeader("RISK ENGINE REPORT");
    prlog("  Generated: " << algo::CurrUnTime());

    // ── Section 1: Portfolio Summary ──

    PrintHeader("PORTFOLIO SUMMARY BY COUNTERPARTY");

    ind_beg(risk_engine::_db_zd_cpty_curs, cpty, risk_engine::_db) {
        double gross_exposure = 0;
        double net_exposure = 0;
        double total_daily_pnl = 0;
        int n_positions = 0;

        ind_beg(risk_engine::cpty_zd_position_curs, pos, cpty) {
            risk_engine::FInstrument &instr = *pos.p_instrument;
            double market_value = pos.qty * instr.price;
            double daily_pnl = pos.qty * (instr.price - instr.prev_close);

            gross_exposure += algo::Abs(market_value);
            net_exposure += market_value;
            total_daily_pnl += daily_pnl;
            n_positions++;
        }ind_end;

        PrintSubheader(cpty.cpty);
        prlog("    Positions:      " << n_positions);
        prlog("    Gross Exposure: " << FmtDollar(gross_exposure));
        prlog("    Net Exposure:   " << FmtDollar(net_exposure));
        prlog("    Daily P&L:      " << FmtDollar(total_daily_pnl));

        ind_beg(risk_engine::cpty_zd_position_curs, pos, cpty) {
            risk_engine::FInstrument &instr = *pos.p_instrument;
            double market_value = pos.qty * instr.price;
            double daily_pnl = pos.qty * (instr.price - instr.prev_close);
            prlog("      " << instr.instrument
                  << "  qty:" << pos.qty
                  << "  mkt_val:" << FmtDollar(market_value)
                  << "  daily_pnl:" << FmtDollar(daily_pnl)
                  << "  (" << instr.name << ")");
        }ind_end;
    }ind_end;

    // ── Section 2: Limit Checks ──

    PrintHeader("RISK LIMIT CHECK");

    int n_breaches = 0;
    int n_warnings = 0;

    ind_beg(risk_engine::_db_zd_cpty_curs, cpty, risk_engine::_db) {
        double gross_exposure = 0;
        double net_exposure = 0;
        double daily_pnl_loss = 0;

        ind_beg(risk_engine::cpty_zd_position_curs, pos, cpty) {
            risk_engine::FInstrument &instr = *pos.p_instrument;
            double market_value = pos.qty * instr.price;
            double daily_pnl = pos.qty * (instr.price - instr.prev_close);

            gross_exposure += algo::Abs(market_value);
            net_exposure += market_value;
            if (daily_pnl < 0) {
                daily_pnl_loss += algo::Abs(daily_pnl);
            }
        }ind_end;

        ind_beg(risk_engine::cpty_zd_risklimit_curs, lim, cpty) {
            algo::Smallstr50 ltype = limittype_Get(lim);
            double actual = 0;

            if (ltype == "gross_exposure") {
                actual = gross_exposure;
            } else if (ltype == "net_exposure") {
                actual = algo::Abs(net_exposure);
            } else if (ltype == "daily_pnl_loss") {
                actual = daily_pnl_loss;
            }

            double utilization = lim.limit_value > 0
                ? actual / lim.limit_value : 0;

            if (utilization > 1.0) {
                prlog("  ** BREACH **  " << cpty.cpty
                      << "  limit:" << ltype
                      << "  actual:" << FmtDollar(actual)
                      << "  limit:" << FmtDollar(lim.limit_value)
                      << "  util:" << FmtPct(utilization));
                n_breaches++;
            } else if (utilization > lim.warn_pct) {
                prlog("  ! WARNING !   " << cpty.cpty
                      << "  limit:" << ltype
                      << "  actual:" << FmtDollar(actual)
                      << "  limit:" << FmtDollar(lim.limit_value)
                      << "  util:" << FmtPct(utilization));
                n_warnings++;
            } else {
                prlog("    OK          " << cpty.cpty
                      << "  limit:" << ltype
                      << "  actual:" << FmtDollar(actual)
                      << "  limit:" << FmtDollar(lim.limit_value)
                      << "  util:" << FmtPct(utilization));
            }
        }ind_end;
    }ind_end;

    // ── Section 3: Exposure by Instrument Type ──

    PrintHeader("EXPOSURE BY INSTRUMENT TYPE");

    ind_beg(risk_engine::_db_zd_instrtype_curs, itype, risk_engine::_db) {
        double type_exposure = 0;
        double type_pnl = 0;
        int n_instruments = 0;

        ind_beg(risk_engine::instrtype_zd_instrument_curs, instr, itype) {
            ind_beg(risk_engine::_db_zd_position_curs, pos, risk_engine::_db) {
                if (pos.p_instrument == &instr) {
                    double mkt = pos.qty * instr.price;
                    double dpnl = pos.qty * (instr.price - instr.prev_close);
                    type_exposure += algo::Abs(mkt);
                    type_pnl += dpnl;
                }
            }ind_end;
            n_instruments++;
        }ind_end;

        if (n_instruments > 0) {
            prlog("  " << itype.instrtype
                  << "  instruments:" << n_instruments
                  << "  exposure:" << FmtDollar(type_exposure)
                  << "  daily_pnl:" << FmtDollar(type_pnl));
        }
    }ind_end;

    // ── Section 4: Summary ──

    PrintHeader("SUMMARY");
    prlog("  Counterparties: " << risk_engine::zd_cpty_N());
    prlog("  Instruments:    " << risk_engine::zd_instrument_N());
    prlog("  Positions:      " << risk_engine::zd_position_N());
    prlog("  Risk Limits:    " << risk_engine::zd_risklimit_N());
    prlog("  Breaches:       " << n_breaches);
    prlog("  Warnings:       " << n_warnings);
    prlog("");
}

void risk_engine::Main() {
    RunRiskReport();
}
```

### Key Patterns in the Source

**Cursor iteration** -- `ind_beg` / `ind_end` macros iterate a linked list
or pool. The cursor variable (e.g., `cpty`) is a reference to the current
element:

```cpp
ind_beg(risk_engine::_db_zd_cpty_curs, cpty, risk_engine::_db) {
    // cpty is a risk_engine::FCpty& for each counterparty
}ind_end;
```

**Nested iteration via group-by** -- iterate all positions belonging to a
specific counterparty by walking its `zd_position` list:

```cpp
ind_beg(risk_engine::cpty_zd_position_curs, pos, cpty) {
    // pos.p_instrument is a pointer to the FInstrument
    double market_value = pos.qty * pos.p_instrument->price;
}ind_end;
```

**Fldfunc accessors** -- composite key fields are accessed via generated
getter functions. `limittype_Get(lim)` extracts the limittype substring
from the `risklimit` primary key (e.g., `desk_a.gross_exposure` ->
`gross_exposure`):

```cpp
algo::Smallstr50 ltype = limittype_Get(lim);
```

**Global count accessors** -- `zd_cpty_N()` returns the number of elements
in the global `zd_cpty` linked list:

```cpp
prlog("  Counterparties: " << risk_engine::zd_cpty_N());
```

## Step 6: Live Data Modification

One of OpenACR's strengths is that all data lives in plain text ssimfiles.
You can modify positions, prices, or limits with `acr` and immediately
re-run the engine to see the effect.

### Add a New Position

```bash
echo 'dev.position position:desk_a.GOLD qty:50 avg_cost:2100' | acr -insert -write
risk_engine
```

Desk A now has a gold position. Check the report to see its exposure increase.

### Update a Price

```bash
echo 'dev.instrument instrument:TSLA price:260.00' | acr -merge -write
risk_engine
```

The `-merge` flag updates only the specified field (`price`) without
resetting other fields. TSLA's price change affects every desk holding it.

### Remove a Position

```bash
acr position:desk_b.TSLA -del -write
risk_engine
```

Desk B's TSLA position is deleted. Check whether removing it brings desk_b
back under its gross exposure limit.

### Tighten a Limit

```bash
echo 'dev.risklimit risklimit:desk_a.gross_exposure limit_value:2000000' | acr -merge -write
risk_engine
```

Desk A's gross exposure limit drops to $2M. This should now trigger a breach.

### Check Integrity After Changes

```bash
acr -check
```

After any modification, `acr -check` verifies that all foreign keys still
resolve correctly.

## Key Takeaways

1. **Composite keys decompose automatically.** The position key
   `desk_a.AAPL` is split into `cpty:desk_a` and `instrument:AAPL` by
   fldfunc expressions (`.RL` and `.RR`). You never write parsing code.

2. **Base inheritance enables zero-cost data loading.** Adding
   `reftype:Base` to an in-memory ctype makes it inherit all ssimfile
   fields. The `finput` + `floadtuples` mechanism reads the `data/`
   directory on startup and populates pools automatically.

3. **Upptr + xref resolves foreign keys at load time.** When a position is
   loaded, the generated `position_XrefMaybe` function looks up the
   counterparty in `ind_cpty` and stores a direct pointer in `p_cpty`. No
   map lookups at query time.

4. **Group-by via Llist is O(1) insertion, O(n) iteration.** The
   `FCpty.zd_position` linked list gives you "all positions for this
   counterparty" without scanning the full position pool. Cascade delete
   ensures removing a counterparty also removes its positions and limits.

5. **The field ordering rule matters.** `Base` must be the first field in a
   ctype. Getting this wrong produces `amc.first_base` errors. When
   restructuring, delete the conflicting field first, add Base, then re-add
   other fields.

6. **Data is live text.** Since ssimfiles are plain text, you can modify
   positions, prices, and limits with `acr -merge -write` and immediately
   re-run the engine. No database server, no migration scripts, no restart.
