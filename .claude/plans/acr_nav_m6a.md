# M6a: gstatic Hook Dispatch (Data-Driven Keybindings)

## Context

acr_nav M1–M5 are complete. `DispatchAction` (`cpp/acr_nav/acr_nav.cpp:214-266`) is a string if-chain with 10 comparisons dispatching actions. This should be function-pointer dispatch via gstatic + Hook, matching the `amc.FGen.step` pattern. Pure refactor — behavior unchanged, architecture improved.

## Approach

### Phase 1: Schema changes

**`data/dmmeta/field.ssim`** — add:
```
dmmeta.field  field:acr_nav.FNavaction.step  arg:""  reftype:Hook  dflt:""  comment:""
```
Using `arg:""` gives parameterless handlers (`void acr_nav::navaction_move_up()`). Handlers access state through `_db` globals. Same pattern as `amc.FGen.step`.

**`data/dmmeta/hook.ssim`** — add:
```
dmmeta.hook  field:acr_nav.FNavaction.step
```

**`data/dmmeta/gstatic.ssim`** — add:
```
dmmeta.gstatic  field:acr_nav.FDb.navaction  comment:""
```

**`data/dmmeta/finput.ssim`** — remove:
```
dmmeta.finput  field:acr_nav.FDb.navaction  extrn:N  update:N  strict:Y  comment:""
```
gstatic and finput are mutually exclusive (verified: no field in the codebase has both).

Run `amc` to regenerate. This produces forward declarations for 12 functions named `acr_nav::navaction_<key>()`.

### Phase 2: Implement 12 action handler functions

Replace `DispatchAction` with individual functions. Each accesses panels via `ind_panel_Find()` and state via `_db`. SESE throughout.

| Function | Body (from current DispatchAction) |
|---|---|
| `navaction_move_up` | `panel.sel_row = max(0, sel_row - 1)` |
| `navaction_move_down` | `panel.sel_row = min(last, sel_row + 1)` |
| `navaction_page_up` | `sel_row -= page` clamped |
| `navaction_page_down` | `sel_row += page` clamped |
| `navaction_switch_panel_left` | if `position > left->position`, switch |
| `navaction_switch_panel_right` | if `position < right->position`, switch |
| `navaction_follow_ref` | push navstack, find target ctype index |
| `navaction_go_back` | pop navstack, restore scroll/sel |
| `navaction_quit` | `_db.running = false` |
| `navaction_filter_start` | stub (empty body) |
| `navaction_filter_cancel` | stub (empty body) |
| `navaction_filter_accept` | stub (empty body) |

Update main loop dispatch from:
```cpp
DispatchAction(keybind->p_navaction->navaction, sel_ct, left, right);
```
To:
```cpp
keybind->p_navaction->step();
```

Delete the old `DispatchAction` function.

### Phase 3: Build and verify

- `acr -check` passes
- `amc` runs clean
- `abt -build acr_nav` compiles
- `amc_vis acr_nav.%` shows `step` Hook on FNavaction
- Manual test: all existing keybinds work identically to M5
- Pressing `/` is a no-op (stub) — expected

## Key design decisions

1. **`arg:""` not `arg:acr_nav.FNavaction`** — handlers don't need the navaction reference, just `_db` globals. Same pattern as `amc.FGen.step`.
2. **Filter handlers are stubs** — M6b implements filter mode. This keeps M6a as a pure refactor with no behavior change.
3. **Keybinds stay flat** — mode-qualified keybinds are M6b scope. The current 13 flat keybind records work unchanged with `ind_keybind_Find(key_name)`.
