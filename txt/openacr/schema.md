## Schema Design and Pitfalls
<a href="#schema-design-and-pitfalls"></a>

Rules for hand-editing or extending the ssim schema and the C++
in-memory database that amc generates from it.

### Pitfalls
<a href="#pitfalls"></a>

- **String defaults need inner quotes** — `dmmeta.field` `dflt` for
  a string is `'""'` for empty, `'"release"'` for a value.
- **fstep on an existing field** — `acr_ed -create -fstep <field>
  [-steptype:<type>]` (default `Inline`).
- **Thash cursors are opt-in.** They are not generated by default.
  Add `dmmeta.fcurs fcurs:<ns>.<Ctype>.<field>/curs comment:""`
  then run `amc`.
- **Fieldwise constructors** — merge `dmmeta.cpptype ctype:<ctype>
  ctor:Y` then `amc`.
- **Bulk updates** — use `acr -merge -write`.  Don't use `-rename`
  twice in one command.
- **No `algo.cstring` in packed protocol messages.** Wire-protocol
  ctypes (`ams.*`) are packed structs; `algo.cstring` is an
  in-memory pointer+length view and can't go on the wire.  Use
  `reftype:Varlen arg:char`; access via the generated getter (e.g.
  `text_Getary(msg)`).  Pattern: `ams.LogMsg.text`.
- **Base a message on `ams.MsgHeader` only in a namespace compiled
  into `lib_prot`.**  A message header is a ctype with a
  `dmmeta.typefld` row.  For each header, amc collects every message
  whose ultimate base is that header and generates a read/print
  dispatch over the set in the header's own namespace — for
  `ams.MsgHeader` that dispatch is `ams::MsgHeaderMsgs`, compiled
  into `lib_prot`.  A message based on `ams.MsgHeader` in an
  app-private namespace joins that dispatch, so `lib_prot` comes to
  reference a symbol only that one app links — every other target
  then fails at link time.  Check namespace membership with
  `acr targsrc:lib_prot/%`.  An app-private message uses a private
  header ctype instead: a `u32` field carrying `dmmeta.typefld`
  plus a `u32` field carrying `dmmeta.lenfld` mirror
  `ams.MsgHeader`'s 8-byte layout, so the wire bytes are unchanged,
  and amc generates the app's own `<Header>Msgs` dispatch.  Pattern:
  `fasttest.TemplateHeader`.  If the messages are packed
  (`dmmeta.pack`), pack the header too — a packed message with an
  unpacked base fails amc (`amc.back_pack` prints the `dmmeta.pack`
  row to insert).
- **xref `via`** — `via` in `dmmeta.xref` is either a single
  pointer field (e.g. `ns.FChild.p_parent`) or
  `<hash_index>/<key_field>`.  The hash_index is the parent's Thash
  field (e.g. `ns.FDb.ind_comptest`); the key_field uses the
  **ssimfile field name** on the child (e.g.
  `atfdb.Tfilt.comptest`), not the in-memory ctype field —
  Base-imported fields lack their own field records.
- **`pnew` for message formatting** — to use `MsgType_FmtByteAry`
  or `MsgType_FmtShm` in a target, insert `dmmeta.pnew` for that
  target+message.  Key: `<target>/<ctype>.<allocator>`, e.g.

  ```bash
  echo 'dmmeta.pnew  pnew:samp_meng/ams.SampMengNewOrderMsg.ByteAry  comment:""' \
      | acr -insert -write
  ```

  Without it, the formatting function isn't generated.
- **Varlen fields must be last** in packed protocol messages.  To
  add a Val field after Varlens, use `acr_ed -create -field ...
  -before <existing>`.  Or reorder via `acr <pat> -rowid` → edit
  rowid → `acr -merge -write`.
- **Reordering ssim records** — `acr <pat> -rowid` prints
  `acr.rowid:<float>` per record; modify and pipe back through
  `acr -merge -write`.  For fields, `acr_ed -create -field ...
  -before <field>` is simpler.
- **Never add xrefs/indexes to ssimdb ctypes.** ssimdb namespaces
  (dmmeta, amsdb, amcdb, dev, …) define wire/schema only — they are
  not in-memory pools.  xrefs and indexes belong on the *wrapping*
  `<lib_or_exe>.F<Ctype>` (the per-tool struct that has `Base
  <ssimdb-ctype>`).  E.g. `field:dmmeta.Field.zs_fcb` is nonsense;
  the right home is `field:amc.FField.zs_fcb`.  Check
  `acr ns -where nstype:ssimdb`.
- **No fconst-on-u8 enum fields in ssimdb tables.**  A `u8` field
  with `dmmeta.fconst` rows prints its symbolic names in the
  ssimfile, but the MariaDB round trip (`normalize_acr_my`) maps
  `u8` to an integer column and rejects the symbol (`Incorrect
  integer value: 'all'`).  Give the enum one of its two supported
  homes: a small ssimfile of its own referenced by `Pkey`, with
  `dmmeta.gconst` for compile-time constants (pattern:
  `amsdb.grptype`, `amsdb.trafficclass`); or, when the field lives on a
  non-ssimdb ctype, a value ctype in a protocol namespace with a
  `printfmt:Raw` cfmt (pattern: `ams.Trafficclass`).  The value-ctype
  form is unavailable inside an ssimdb namespace — every ctype
  there must be an ssimfile (`amc.need_ssimfile`).

### Allocation rules
<a href="#allocation-rules"></a>

- **Always call `XrefMaybe` after allocating.**

  ```cpp
  T &rec = pool_Alloc();
  rec.field = ...;
  pool_XrefMaybe(rec);   // inserts the record into all indexes
  ```

  Exception: the record is deleted immediately without being used.

- **Tpool vs Lary** — Tpool recycles memory but lacks `RemoveAll`;
  use Lary when you need to clear all records between iterations.
