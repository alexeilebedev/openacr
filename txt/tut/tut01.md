## Tutorial 1: Parts and projects
<a href="#tutorial-1-parts-and-projects"></a>

> **Live tutorial, and it edits the tree.**  Every
> `inline-command:` block below is executed in a sandbox by
> `abt_md` when this page is rebuilt, and the output shown is
> the actual output of that run.  The commands create targets,
> ctypes and fields, so running them in your own checkout
> changes its schema and its sources.  Reproduce the session in
> a sandbox instead: `wt tut_make -reset "bash -l"` gives you a
> shell in one, reset to match your current directory, and
> nothing you do there reaches your working tree — see
> [wt](/txt/exe/wt/README.md).

In this tutorial we create a new program and its in-memory
database through shell commands.  The program is a simple
parts-and-projects application with automatic group-by and
cascade-delete operations.  The data structure is described
entirely through ssim tables; the C++ that manipulates it is
generated by `amc`.

The example comes from Codd's classic 1970 paper
[A Relational Model of Data For Large Shared Data Banks](https://www.seas.upenn.edu/~zives/03f/cis550/codd.pdf).

```c++
//

//
// Target: samp_tut1 (exe)
// Exceptions: yes
// Source: cpp/samp_tut1.cpp
//

#include "include/algo.h"
#include "include/samp_tut1.h"

samp_tut1::Partproj *samp_tut1::CreatePartProj(samp_tut1::Part &part, samp_tut1::Proj &proj) {
    Partproj *pp = &partproj_Alloc();
    pp->p_part = &part;
    pp->p_proj = &proj;
    if (!partproj_XrefMaybe(*pp)) {
        partproj_Delete(*pp);
        pp=NULL;
    }
    return pp;
}

static void Show() {
    prlog("list of projects and their parts");
    ind_beg(samp_tut1::_db_zd_proj_curs,proj,samp_tut1::_db) {
        prlog("  project "<<proj.proj);
        ind_beg(samp_tut1::proj_zd_partproj_curs,partproj,proj) {
            prlog("    has part "<<partproj.p_part->part);
        }ind_end
    }ind_end;
    prlog("list of parts and their projects");
    ind_beg(samp_tut1::_db_zd_part_curs,part,samp_tut1::_db) {
        prlog("  part "<<part.part);
        if (samp_tut1::Partproj *partproj = part.c_partproj) {
            prlog("    has project "<<partproj->p_proj->proj);
        }
    }ind_end;
    prlog("");
}

void samp_tut1::Main() {
    samp_tut1::Proj &proj1 = samp_tut1::ind_proj_GetOrCreate("proj1");
    samp_tut1::Proj &proj2 = samp_tut1::ind_proj_GetOrCreate("proj2");

    samp_tut1::Part &part1 = samp_tut1::ind_part_GetOrCreate("part1");
    samp_tut1::Part &part2 = samp_tut1::ind_part_GetOrCreate("part2");
    samp_tut1::Part &part3 = samp_tut1::ind_part_GetOrCreate("part3");

    // assign parts to projects
    samp_tut1::CreatePartProj(part1,proj1);
    samp_tut1::CreatePartProj(part2,proj1);
    samp_tut1::CreatePartProj(part3,proj2);

    // list parts
    prlog("initial setup");
    Show();

    // delete a part -- this will remove it from any projects
    // that reference the part
    prlog("deleting part1");
    part_Delete(part1);
    Show();
    // let's not reference part1 beyond this point

    // delete a project
    prlog("deleting proj2");
    proj_Delete(proj2);
    // now part3 will become unassigned
    Show();

    prlog("deleting proj1");
    proj_Delete(proj1);
    // at this point, part2 and part3 remain,
    // but they aren't attached to any project
    Show();
}
```

### Summary
<a href="#summary"></a>

This tutorial demonstrated:

- Creating a new executable, its ctypes, and its indexes from
  the command line — the shell as the IDE.
- Automatic insertion into a global list when a record is
  created.
- Automatic removal from a global list when a record is
  deleted.
- Automatic group-by by following a reference.
- Cascade-delete: removing a Part removes any Partprojs
  referring to it.
- Custom (Tpool-backed) allocation and deallocation.

We also (deliberately, for the demo) declared unused hash
indexes `samp_tut1.FDb.ind_proj` and `samp_tut1.FDb.ind_part`.
