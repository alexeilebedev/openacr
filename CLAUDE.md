# CLAUDE.md

This file provides guidance to Claude Code when working on the OpenACR codebase.

## What This Is

OpenACR is a meta-programming framework where `amc` (Algo Model Compiler) generates most of its own source code from ssimfile tables — roughly 15–25 lines of C++ per line of specification. 15+ years in production, mission-critical systems.

The core insight: **everything is data.** New capabilities come from adding records, not writing code. The cost of code grows exponentially (COCOMO); orthogonal factorization is the primary tool for keeping it manageable.

Use `/acr` skill for architectural guidance, design thinking, and development patterns.

## The Mental Model

Take any running program and freeze it. Look at its memory. Everything sorts into piles of typed structures: windows, lines, connections, sessions. Each pile is a table. Each structure is a record. The program IS an in-memory database.

When the program runs, each step transforms the previous database state into the next: create a line, delete a window, modify a field. The infinite actions users perform are composed of simple verbs on simple categories. The language doesn't matter. The structure is what matters.

Describe the program as an in-memory database first, language second. The structure IS the design.

## Commands

```bash
# Build
ai                           # Full bootstrap + build (the main command)
make                         # Release: ai && abt -cfg:release -install %
make CFG=debug               # Debug build
abt -build -install <target> # Build specific target

# Test
normalize                    # All normalization tests
normalize comp               # Component tests
normalize coverage           # Coverage tests
normalize memcheck           # Memory leak checks (valgrind)
atf_ci -cijob:<job>          # Specific CI job

# Code Generation
amc                          # Regenerate cpp/gen/ and include/gen/ from data/
acr <table>                  # Query ssimfile database
acr -check                   # Check referential integrity
acr_ed -create ...           # Scaffold new components (acr_ed -help for usage)

# Cleanup
make clean                   # git clean -dfx build temp
```

**PATH**: `export PATH=$PATH:bin`

## The Development Loop

1. Edit ssimfile records in `data/` (meta-schema in `data/dmmeta/`)
2. Run `amc` to regenerate `cpp/gen/` and `include/gen/`
3. Build with `ai` or `abt`
4. Test with `normalize`
5. `git diff cpp/gen/` — review generated changes
6. Commit both schema and generated code

**Never hand-edit `cpp/gen/` or `include/gen/`** — overwritten by `amc`.

**When modifying amc itself**, use `sandbox amc -reset -diff -- amc` to test safely. A broken amc can prevent itself from being fixed.

## Ssimfile Format

Line-oriented, set-based, SQL-equivalent:

```
namespace.table  primary_key  [key:value ...]

dmmeta.ns     ns:amc       nstype:exe   license:GPL  comment:"Algo Model Compiler"
dmmeta.field  field:amc.FDb.ind_ns  arg:dmmeta.Ns  reftype:Thash  dflt:""  comment:""
```

Any concatenation, permutation, or subset of ssimfile lines is valid. First field is always the primary key. Stored in `data/<namespace>/<table>.ssim`. **Singular everywhere** — the table is `field`, not `fields`; one element is also `field`. The table name is a piece of the element's name. See `txt/ssim.md` for full specification.

## Architectural Rules

- **Everything is data.** Adding a code branch means you're missing a record.
- **One record per thing.** No sub-formats, no nested structures, no comma-separated lists.
- **Self-describing.** The meta-schema uses its own format. `dmmeta.field` has records for its own fields. amc generates most of its own source code — the generated `cpp/gen/` is committed to git as the bootstrap.
- **Deterministic output.** amc produces byte-identical output on every run.
- **Uniform contracts.** All generators share the same `void()` function pointer interface — see `data/amcdb/gen.ssim`.
- **No intermediate representation.** Generators build strings directly via `<<` operators. No AST.
- **Generation/IO split.** Generators write to buffers; a separate writer handles files.
- **Never edit gen/.** Generated code is overwritten by amc.

## Coding Style

- **SESE (Single Entry, Single Exit):** No early returns. Code flows top to bottom. `return` mid-function is goto in disguise.
- **Group by action, not condition:** `B; if(A){C} else {D}` — not `if(A){B;C} else {B;D}`.
- **Data as stylesheet:** Similar code paths differing only in a value → one path, data supplies parameters.
